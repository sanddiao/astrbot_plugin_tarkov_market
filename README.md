# AstrBot 插件 · 逃离塔科夫物价查询

给 QQ 群 / 频道用的塔科夫（Escape from Tarkov）物价查询插件。**定向查询任意物品的跳蚤价与商人收购价**，顺带告诉玩家"卖给谁更划算"，并附该物品的任务 / 兑换 / 合成 / 藏身处用途。

价格**每次查询前自动取最新**（利用 ETag 协商，未变价时零流量），不用配任何定时任务；断网时自动退回离线库照常可查。

## 指令一览

| 指令 | 别名 | 说明 |
|---|---|---|
| `/塔科夫 <物品名> [数量]` | `/tk` `/tarkov` `/塔科夫物价` | 查物价（主功能） |
| `/塔科夫用途 <物品名>` | `/tk用途` `/tku` | 查用途明细 |
| `/塔科夫榜 [n]` | `/tk榜` `/物价榜` | 物价排行（默认前 10，最多 30） |
| `/塔科夫刷新` | `/tk刷新` `/tkrefresh` | 强制重拉实时价（约 5~10 秒，日常无需手动） |
| `/塔科夫信息` | `/tk信息` `/tkinfo` | 显示当前数据集概况 |

群里记得带唤醒前缀或 @ 机器人，例如 `/塔科夫 吗啡`。

## 搜索怎么做的

四级匹配，越靠前越优先（同级短名字优先）：

1. **完全一致**（物品 ID 或名称）
2. **前缀匹配**（`螺丝` → 螺丝刀）
3. **子串匹配**（`水管` → 军用级水管）
4. **顺次字符匹配**（≥3 字符，容错输入，如 `m4a1`）

匹配到多个时会列出候选清单让你补全称；像「已密封的武器箱」这种有几十种变体的物品，会折叠成一条并标注变体数，取价格最高者展示。

## 安装

1. 把整个目录放到 AstrBot 的插件目录（通常是 `data/plugins/astrbot_plugin_tarkov_market`）
2. 确认 `data/items.json` 存在（已随仓库提供；如缺失见下方"重建数据"）
3. 重启 AstrBot，日志里看到 `[tarkov_market] 插件已加载` 即为成功

**零第三方依赖**：全部用 Python 标准库实现，不用装 openpyxl / requests。

## 数据来源

- **离线库 `data/items.json`**：由 `item_usage.xlsx`（物品ID / 物品名 / 用途类型 / 用途详情 / 物品卖给商人的价格 / 当前跳蚤价格）生成，**任何时候都能查，不需要联网**。
- **实时价 `data/live_prices.json`**：从 `json.tarkov.dev` 拉取（tarkov.dev 前端自用的静态数据包，无需 API Key）。

### 价格自动保鲜：每次查询前自动取最新价

不需要配任何定时任务。**每次查价前插件会先确认一次线上有没有变价**，流程是：

```
查询进来 → 有缓存吗？
   ├─ 没有        → 全量拉一次（首次约 8 秒，会提示"首次查询，正在拉取…"）
   └─ 有          → 距上次检查 > 60 秒？
         ├─ 否    → 直接用缓存，秒回
         └─ 是    → 带 ETag 问一句"变了吗"（约 2 秒）
                       ├─ 304 未变 → 缓存就是最新的，零流量，直接用
                       └─ 200 变了 → 整包更新后再回答
```

关键在于 tarkov.dev 支持 **ETag 协商**：数据没变时服务端回 304，一个字节都不用下。实测：

| 场景 | 耗时 | 传输 |
|---|---|---|
| 首次查询（无缓存） | 8.0 秒 | 1.8 MB（gzip） |
| 后续查询（线上未变价） | 2.0 秒 | **0 字节** |
| 60 秒内的连续查询 | < 0.01 秒 | 不发请求 |

所以"每次查询前查一次"的成本极低，语义上等价于**每次都拿最新价**。

想调整的话改 `tarkov_data.py` 顶部两个常量：

```python
AUTO_REFRESH = True          # 关掉就不自动检查，纯用离线库 + 手动 /塔科夫刷新
REFRESH_MIN_INTERVAL = 60    # 检查的最小间隔（秒）；改成 0 = 每条消息都真发一次请求
```

> 顺带一提：`urllib` 默认**不请求 gzip**，最初整包要下 16.5MB、耗时 22 秒；加上
> `Accept-Encoding: gzip` 后只要 1.8MB（压缩比 9 倍），这是自动保鲜能成立的前提。

> 关于 GraphQL：`tarkov_spider.py` 里的备用源 `api.tarkov.dev/graphql` 目前不可用（实测返回 `422 Unprocessable Entity` / `GraphQL server unavailable`，随请求内容而变），因此本插件的在线刷新**只走 json.tarkov.dev 静态包**这条路。
>
> 这不影响你的数据：**主源 json.tarkov.dev 一直是爬虫的首选**（`tarkov_spider.py` 的 `source=auto` 策略就优先探测它，GraphQL 只是兜底）。`item_usage.xlsx` / `prices.csv` 里的价格全部来自这条主路径，从未经过 GraphQL。

### 价格的本质（使用时请注意）

| 字段 | 含义 | 更新频率 |
|---|---|---|
| `avg24hPrice`（插件里的「跳蚤市场价」） | 过去 **24 小时**玩家上报成交的**均价** | 小时级滚动更新 |
| `lastLowPrice`（「近期最低价」） | 近期最低挂牌价 | 同上 |
| 商人收购价 | 游戏数据解包所得，基本不变 | 随版本更新 |

数据来源是 **社区聚合**（tarkov.dev 汇总的玩家上报价），不是 Battlestate 官方接口——塔科夫没有公开的实时物价 API。

**验证结论（2026-10-18 实测）**：数据包内 `updated` 字段显示当次快照为 `2026-10-18T08:28:10Z`（UTC），即北京时间当天 **16:28**，几乎是实时；抽样对比 2 小时前的 `prices.csv`，5 件里 4 件跳蚤均价已漂移（如 LEDX `603,701 → 621,106`），而商人收购价纹丝不动。这印证了：**跳蚤价会自己动**，所以插件默认每次查询前自动确认一次（见上）。

## 重建 / 更新离线数据

拿到新版 `item_usage.xlsx` 后：

```bash
cd AstrBot 插件目录
python tools/build_dataset.py /path/to/item_usage.xlsx
```

脚本用标准库（`zipfile` + `xml.etree`）直接解析 xlsx，**不需要 openpyxl**。默认输出到 `data/items.json`。

## 常见问题

**发了指令没反应，反而是大模型在回复？**
说明插件没被加载。检查：控制台有没有 `[tarkov_market] 插件已加载` 这行；插件是否加进了 `plugin_set`；`metadata.yaml` 里 `name` 是否与目录名一致；指令是否带了 `/` 前缀。

**提示 `缺少数据文件 data/items.json`**
运行上面的 build_dataset.py 重新生成即可。

**想接更多字段（占格、重量、48h 涨跌幅）？**
这些字段在实时价里有，执行一次 `/塔科夫刷新` 后再查就会带出来。
